Fragline: engine provenance, corresponding source and changes
=============================================================

ENGINE (GNU GPL v2, full text in ENGINE-LICENSE.txt)

  websockets-doom.wasm.gz   Chocolate Doom compiled to WebAssembly, gzip-compressed for download.
                            The browser decompresses it back to the original, unmodified binary:
                            sha256 4a55e4381d374b9bf347116e8c6f52547bb990fd7fc28a5e21af354830f80f78
  websockets-doom.js        Emscripten loader for the binary above (modified, see below)

  Where the binary came from:
    - Taken from the published GitHub Pages build of Saketh-Chandra/doom-wasm-pwa
      (branch gh-pages, commit 5b1e1fe7385b6f0b19d60dece6adbf88f6842e20, 2023-03-09)
    - Built from source revision Saketh-Chandra/doom-wasm-pwa@a77edfd8bbc7
    - A fork of https://github.com/cloudflare/doom-wasm (GPL-2.0)
    - A WebAssembly port of https://github.com/chocolate-doom/chocolate-doom

  Corresponding source: the tree at Saketh-Chandra/doom-wasm-pwa@a77edfd8bbc7. Because that is a
  third party's repository, anyone redistributing Fragline should keep their own copy of that exact
  source tree available alongside the binary (GPL v2 section 3).

  Changes to websockets-doom.js (2026-10-30, Fragline):
    - _emscripten_date_now() adds a random per-tab offset to the wall clock. The engine seeds its
      network player id from the clock, so players who started together received the same id and
      were rejected by the relay. Game timing uses the monotonic clock and is unaffected.
  The WebAssembly binary itself is unmodified.

FRAGLINE'S OWN FILES

  fragline.wad    Title screen only (TITLEPIC), generated by tools/make_art.py
  game.js, index.html, style.css, controller.js, sw.js, src/index.mjs, lan_server.py

No commercial Doom data (doom.wad, doom2.wad) is included or needed.
