# Local Raspberry Pi setup

The Pi serves the game files and relays game packets; each laptop runs the whole game in its browser. Rooms hold 2–4 players. The local server and matches have been tested in headless browsers on Linux; Raspberry Pi hardware, real Wi-Fi and physical controllers have not yet been tested.

## Network

Use Pi 5 as the main server. Connect its Wi-Fi to the same router as the two laptops. The Pi 4 can connect directly to the Pi 5 by Ethernet for backups or a separate instance; this does not combine their CPU/RAM. Do not split one match across both servers. The direct Ethernet link does not replace the laptops' path to the Pi 5.

For that optional direct link, assign unused addresses on a separate subnet (for example Pi 5 Ethernet 10.77.0.1/24 and Pi 4 Ethernet 10.77.0.2/24), with no Ethernet default gateway; retain Wi-Fi as the Internet route. Check existing subnets before choosing these values. These addresses are examples, not configured settings. Use the Pi 5 Wi-Fi address when sharing with the laptops. Guest/client-isolated networks can prevent access.

## Start on Pi 5

Use Raspberry Pi OS 64-bit. Copy this entire project folder to the Pi, including public/ and lan_server.py. In its terminal, from that folder:

```sh
sudo apt update
sudo apt install python3 python3-venv
bash start_pi.sh
```

Initial dependency installation requires Internet. Once the environment exists, you can start fully offline with:

```sh
.venv/bin/python lan_server.py --port 8765
```

Keep the server running. Every laptop opens the printed Pi Wi-Fi URL, for example http://192.168.1.50:8765. One player creates a room (choosing map, player count and time limit) and shares the link or code; the others join. The match starts when everyone has joined. All tabs must remain visible. Do not use localhost on the laptops: that points to each laptop, not the Pi. Reserve the Pi Wi-Fi address on your router if possible.

No external fonts or scripts are needed by the local page. Game data, controller code and touch-control dependencies are included. The server keeps the files in memory, sends text files gzip-compressed and answers repeat requests with 304 Not Modified, so reloads are quick over Wi-Fi. The first load is about 11 MB per laptop.

## Controllers and the offline cache need trusted HTTPS

Modern browsers restrict the Gamepad API and service workers (the offline cache) to secure contexts: HTTPS or localhost. Plain HTTP at the Pi IP supports keyboard/mouse; it cannot promise controller access. The public Cloudflare website already uses HTTPS, but using it still routes the match through Cloudflare.

For controller support while keeping gameplay local, install Caddy on the Pi following https://caddyserver.com/docs/install and adapt Caddyfile.example to the reserved Pi Wi-Fi address. Its configuration uses tls internal and proxies HTTP and WebSockets to 127.0.0.1:8765. Run the backend as above and Caddy with your adapted configuration. Open https://PI_WIFI_IP on both laptops.

Both laptops must trust the root certificate generated by YOUR Caddy instance. Caddy documents where its root.crt is stored and how trust works: https://caddyserver.com/docs/automatic-https. For the packaged Caddy system service, the usual certificate location is /var/lib/caddy/.local/share/caddy/pki/authorities/local/root.crt. Copy only root.crt, never the CA private key, to the laptops and have their owner install it in the appropriate trusted root store. Confirm its fingerprint against the Pi before trusting it. Do not bypass browser certificate errors. Browser trust behavior differs across Windows/Linux/browser combinations, so verify the page loads with no certificate warning and displays a controller connection after pressing a button.

## Windows host alternative

Run Start Wi-Fi Game.cmd on the Windows laptop (Python 3.11+ required). It installs websockets if missing and prints a local link. If Windows asks, allow the server on the private network you intend to use. No firewall settings are changed by this package. Remote laptops still need trusted HTTPS for controllers. Keyboard/mouse works over the local HTTP address.

## Tests

```sh
npm test
```

Node is needed only for the tests and Cloudflare development, not to run the Python LAN server. These tests do not establish physical controller compatibility, real Wi-Fi performance, or Raspberry Pi stability.
